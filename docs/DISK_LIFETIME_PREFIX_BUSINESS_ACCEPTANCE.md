## 1. 用户确认的目标与边界

目标是尽量保住同一批、具有前缀依赖关系的 KV cache，使请求能够复用更长的连续
前缀，而不是只提高零散对象命中数。用户确认：链 A → B → C → D 中 B 缺失时，
即使 C、D 仍在缓存，也只能复用 A，后面的计算不能靠这两次孤立命中免除。

- “同批”不是任意相同写入时间的对象集合，而是有明确请求/前缀依赖的有序逻辑块。
- 同批尽量完整保留是服务于前缀复用的目标；不是必须整批命中才有收益，也不是
  当前淘汰器已具备批次识别、链级评分、原子驻留或整链淘汰能力的证明。
- 跨请求共享前缀、不同分支、不同长度请求必须保留真实身份与顺序。不能把同一批
  所有对象存在数量直接当作连续长度，也不能强求只保留最长链而牺牲全部短请求。
- 对象、逻辑块、请求三种计量粒度分开；一个逻辑块可能需要多个分片/对象共同完整。

四个等长块、每块 16 token 的示意（不是实测）：

| 有效块状态 A/B/C/D | 对象级命中 | 连续可复用 token | 完整前缀命中 |
|---|---|---|---|
| hit / hit / hit / miss | 3/4 | 48/64 | 否 |
| hit / miss / hit / hit | 3/4 | 16/64 | 否 |
| miss / hit / hit / hit | 3/4 | 0/64 | 否 |
| hit / hit / hit / hit | 4/4 | 64/64 | 是 |

这里的对象级命中仅指有完整状态可见时的示意。如果真实客户端在首个 miss 后不再读取
后缀，未发起项应记 not_attempted；批量已探测或在途的后缀按真实终局记录，
即使 hit 也标明未形成有效前缀，不能把“未采用”一律改成“未尝试”。

## 2. 请求级计算合同（离线 V1 仅实现无本地缓存的线性单对象子集）

对事前 trace 中每个业务请求 r，先定义无本地前缀的简单线性模型，再扩展本地贡献：

1. 固定其可缓存、符合模型/版本/namespace/代际要求的前缀，按依赖顺序列出逻辑块，
   块 token 长度为 t[r,i]，总目标 T[r] 为这些长度之和。padding、不缓存尾部、
   采样保留尾部及对齐规则必须来自客户端合同，不能用整个 prompt 长度代替。
2. 每个逻辑块完整，要求该候选边界下 LOAD 所需的全部分片/对象匹配且可用；不能
   因某个 TP/PP/CP 分片存在就把整个逻辑块记 hit。混合状态模型还须遵守候选长度
   对应的 load mask/checkpoint 规则，不能只套用简单线性分块假设。
3. p[r] 是从链首起连续完整块的最大个数；首个不完整块之后，不再累计任何收益。
   lookup 候选前缀 L[r] = sum(t[r,i], i <= p[r])。
4. 候选存在不等于传输成功或引擎采用成功。无本地前缀的简单模型中，实际生效复用
   U[r] 必须由客户端/引擎确认，且不超过 L[r]；加载期间丢失、读失败或引擎丢弃
   不能按 lookup 长度宣称已省下计算。没有实际采用证据只能报告 L[r]，U[r] 标未测。
5. 有本地缓存时，C[r] 是目标范围内已证实来自本地缓存且实际采用的连续前缀，L[r] 是外部 lookup
   候选的链上终点，两者都以链首为坐标，不是可相加的增量。本地前缀不要求再次
   读盘。简单连续模型（lookup 前尚无本请求重算进度）中，外部新增实际采用量 E[r] <= max(0, L[r]-C[r])；总实际
   复用 U[r] = C[r]+E[r]，且 0 <= U[r] <= T[r]。例如 C=32、L=16 时，E=0、
   U=32，并非把 U 截为 16；C=16、L=48 且补齐成功时，E=32、U=48，不是 64。
   C/E/U 分表，外部缓存新增收益以 E 为准，端到端收益以 U 为准；RAM 开启时 E
   仍不自动等于纯磁盘贡献，需区分实际来源。F01 事前明确选用哪项。
   已计算进度另记：scheduler 的 num_computed_tokens 可能含本请求重算 token，
   不能直接当作 C 或缓存收益。存在此类进度或混合模型时，须以实际来源、采用
   边界和引擎依赖合同核验，不能强套简化公式。若不能
   稳定区分本地贡献，只报端到端总复用，不把它冒充磁盘策略独立贡献。

### 状态、时间和分母

- 请求集合 N 由同一不可变业务 trace 及事前测量窗口决定，不按策略实际命中、完成
  快慢或找到链身份与否挑选。只比较两组成功交集会隐藏超时/排队/失败，禁止这样
  构造主收益分母；所有计划请求保留终局与资格。
- 确定 miss、网络/I/O error、timeout、取消、迟到、未尝试、未知分别记录。不能把
  error 当作 cache miss，也不能因这些项没有 U[r] 就静默从 N 中删除。
- 未知实际复用不能猜为 0 或成功。完整请求分母、已知/未知数量及原因全部公开；
  若主指标依赖未知 U[r]，主判定为不可判定，并另报已知项贡献/全分母的保守下界，
  该下界不等于真实均值。可靠证明“未复用”的失败才可记 U[r]=0。
- 首次业务读取按当时状态判定，不能在回填后回写为首次 hit。回填、校验 GET、重试
  是辅助操作，不生成新的业务请求或增加业务命中分子；仍进入完整传输/写入成本账。
- 不把异步逐对象查询当同一时刻的原子驻留快照；保留每次查询/加载时间、代际与
  终局。实际请求获得的前缀才是业务事实，瞬态驻留另作诊断。
- trace 尾部首次复用尚未到期的链保留显式右删失记录，不算 miss。主业务请求窗口
  事前固定；不能延长较慢策略以获得更多到期请求，或用实际完成窗口重定分母。
- 原始链/请求/对象 ID 放离线明细，不放 Prometheus 高基数标签。业务标识须脱敏。

## 3. 指标与验收优先级

下表均为待实现的计量合同，非新增生产指标；百分数仅是单位，不是已批准门槛。
所有适用公式要求资格明细完整，且涉及的 U[r] 已可靠测得；零分母标 N/A，不标通过。
若事前选外部新增 E 作主指标，另报相应 E 分子，仍使用同一 trace 的 N/T 分母；
不能按各组本地命中结果或 T-C 重选请求资格、改变主比较分母。
T[r]=0 的请求单列数量和原因，不纳入前缀收益分母，仍保留在整体请求终局账。

| 层级 | 指标及口径 | 用途/限制 |
|---|---|---|
| 主业务候选 | 请求平均实际连续复用 token：sum(U[r])/N | 反映每个请求获得的连续复用；本地/外部/总量分表 |
| 主业务候选 | token 加权复用率：sum(U[r])/sum(T[r]) | 衡量目标 token 中实际复用的比例；不得与请求平均比例混称 |
| 补充 | 请求平均复用比例：sum(U[r]/T[r])/N | 每个请求等权，避免只有长请求决定结论；与上行同时报告 |
| 补充 | 完整目标前缀命中率：count(U[r]=T[r])/N | 完整的是可缓存目标，不是包含不缓存尾部的整个 prompt |
| 补充 | 首次断点位置、连续复用长度分布 | head/middle/tail、无断点分别报告；长短链与热点/延迟组分层 |
| 业务成本 | 目标未复用 token：T[r]-U[r] | 合成负载可测“需重算 token 代理”；不是实测引擎重算量 |
| 实测成本 | 引擎实际重算 token、TTFT、有效完成吞吐 | 需真实引擎事件和时间，不能由固定每 token 成本伪造 |
| 成本/护栏 | 回填次数/字节、网络与元数据 I/O、延迟、CPU、内存、热点损失 | 按 F02–F05 分别登记；逻辑 payload 非 NAND 写放大 |
| 对象诊断 | KV/key/bytes 命中、链内孤立剩余块、各评分档分布 | 解释行为，不单独决定 F01 胜负 |

**建议主判据：**事前选择“实际连续复用 token”或其 token 加权比例中的一项作为
F01 主收益，并登记最小有意义增益；另一项及短链、长期复用、热点等关键分层设
事前回退上限。不能看完结果再挑指标；两项共用分子，不算两个独立收益证据。
完整命中率是重要补充，但不能用它掩盖大部分请求仍能复用较长前缀的收益。

F01 至少一项独立业务收益达到已冻结幅度，其余回退受限；不能靠微小 token 增益
抵消严重 TTFT、写入成本或短请求损失。错误 bytes/错代/错误 ACK 等安全问题零容忍。
没有真实引擎时，只能对“合成连续前缀代理收益”给出范围结论；不能声称 TTFT 或
实际计算成本更优，更不能仅凭模拟完整链命中就放行生产。

### 数值建议的边界

本轮建议指标方向和程序，不编造增益百分比或成本权重。现有探索结果已公开，本代理
不是盲态阈值制定者。具体最小增益、各分层最大回退、p99/RSS/写入预算、样本量及
统计功效，须按现有独立职责/可见性规则，结合旧 baseline 和业务需求登记并冻结。
同一链的多次请求、共享前缀的分支相互相关，不能把每个 KV 当独立样本扩大显著性。
统计单元/配对轮次/按共享前缀家族聚类的方法事前确定；至少三轮并不自动证明统计功效。
基线为零时报告绝对差并用事前绝对判据，不计算无意义的相对百分比。

## 4. 必须覆盖的验证场景

这是完整工具/单测与后续 RDMA 诊断的覆盖要求，不表示离线 V1 全部已执行。
已执行与未覆盖项目以[离线验证范围](DISK_LIFETIME_PREFIX_OFFLINE_VALIDATION.md)为准。

| 场景 | 必须证明什么 |
|---|---|
| 同样 KV hit 数，不同缺口位置 | 链首/中间/尾部缺失得到不同连续收益；后缀孤立 hit 不计 |
| 全 hit、全 miss、单块链、零可缓存 token、变长块 | 公式/边界/完整命中与分母正确，非整齐等长块限定 |
| 不完整分片、错代、lookup 后失效、LOAD 失败 | 不虚报完整块或实际复用；错误分类而非伪装 miss |
| 共享前缀分叉、相同批次 ID 但不同链、重复请求 | 复用依赖正确；每个真实请求各计一次，不按唯一链去重收益 |
| 本地已有前缀与磁盘前缀重叠、非缓存尾部 | 不重复累计 token；单列本地/外部，不夸大磁盘贡献 |
| 同批写入跨度与批内压力、乱序完成、部分 PUT 失败 | 以实际 ACK 和可用状态判定，不假设原子整批驻留 |
| 持续新链＋热点共享前缀＋延迟重访 | 在同一容量竞争中比较链级收益，不只孤立 185 秒对象 |
| 长短链/多尺寸/不同请求频次与复用间隔 | 同报请求等权、token 加权及分层，避免平均数掩盖伤害 |
| 先 miss 后回填再重访 | 首次与再次收益分开，回填不倒改首次状态，不双计校验 |
| 固定窗口末端、超时、失败、队列满/删失 | 资格和完整请求终局不依赖策略结果，不静默丢分母 |

首个模拟样本可以固定无本地缓存、单逻辑块单对象、线性前缀，以便人工核算；必须
标明适用范围，不能代替全部分片/混合模型或实际引擎验证。链长、token/块、写入
间隔、共享率、复用间隔和容量/在途链比例是独立输入；45/185/600 秒可作为既有
诊断分层保留，但不是线上分布，也不能仅缩短参数让 lifetime 赢。

真实业务收益在首个缺失处截断，实际探测、在途读取和后缀重算/回填遵循客户端
合同；这里不要求现有客户端将批量查询改成逐项短路。两组保持同一基础请求到达
trace；miss 导致额外操作允许不同，但须完整关联计量。验证器不得为获知后缀驻留
而额外发出可能计热的 GET，再把这种新负载冒充原客户端行为。原客户端本来就有
的批量 EXISTS/GET 则如实保留和计量：探测成功不等于连续复用或实际采用。

## 5. 历史证据如何解释

[持续新到达混合诊断](DISK_LIFETIME_CONTINUOUS_REUSE.md)及此前热点、延迟复用
报告按独立 KV 对象设计，没有请求级有序前缀/分片依赖、token 权重和引擎实际采用
账。其状态校验、原始分母、热点损失、回填及 I/O 结果仍有效，不能删掉不利结果。

但它们不能直接重算连续前缀收益：缺少链身份和依赖，不能事后按 key 顺序或同一
写入批次“补造”前缀链。旧观察“等对象 miss 成本下 legacy 在该负载较好”仅是
独立对象假设下的描述，不是客户端前缀收益排名；保住部分 185 秒对象也不是
lifetime 前缀收益更高的证据。两种策略的业务优劣当前均未在该新口径下证明。

现有连接器已有相关边界，但不是本轮新验证：
[worker.lookup](../integration/vllm/src/dfkv_vllm/worker.py)检查候选长度对应对象/分片完整性，
按首个不完整逻辑块截断；
[scheduler.get_num_new_matched_tokens](../integration/vllm/src/dfkv_vllm/scheduler.py)
区分已计算 token，并处理不缓存的采样尾部。本文只是据此避免“一个 key 即一个
完整业务块”的错误假设，不声称覆盖所有模型、各进程协商或加载终局。

## 6. 待提供输入与下一步

### 用户/业务侧输入（可渐进补齐，不阻塞离线公式单测）

1. 一条典型前缀链的实际例子：逻辑块顺序、每块 token、所需对象/分片映射，以及
   模型/代际和 namespace 边界。“同批”在业务中怎样标识，不默认服务端已知道。
2. 长短链/共享前缀/分支、请求频次、写入跨度和首次/再次复用间隔的代表性分布；
   可先给脱敏样例，再决定合成范围，不能用我们的压力参数冒充线上比例。
3. 客户端首 miss 后的真实重算与写回协议，本地缓存贡献、加载失败处理，以及能否
   提供实际采用 token/重算 token/TTFT 字段。不提供则这些项保持未测。
4. 对平均收益、短请求/热点损失、延迟和写入成本的容忍要求。具体正式阈值仍需
   独立负责人按现有隔离程序登记；用户描述目标不等于自动完成独立签署。

### 首个离线小闭环与后续扩展

首个限定子集已落实为[离线工具与单测](DISK_LIFETIME_PREFIX_OFFLINE_VALIDATION.md)。
原计划的**离线前缀链 trace＋独立计算器＋人工可核算的单测**要求仍是：固定有序身份/代际/
长度与状态字段，计算候选前缀、实际复用（缺证据明确未知）、完整分母和成本。
覆盖第 4 节可离线验证的正常/边界/篡改拒绝案例；接 fake backend 验证首 miss
处收益截断与真实客户端操作合同，不通过验证器额外 GET 给后缀加热。仍不连真实服务、不改生产算法。

工具合同与单测审查通过后，再单独安排 RDMA/RXE＋io_uring 的链级对照；原有温控、
身份/磁盘绑定核验及完整原账要求不放宽。只使用宿主 `/mnt/disk2`、`/mnt/disk3`
专属目录，持续禁止压测宿主 `/mnt/disk1` 和 `/dev/nvme1*`；GPU 不做，TCP 不测。
正式 A/B 仍需完整旧 baseline、目标资源、职责/隔离审计、F01–F05 数值与统计方案、
冻结 manifest 和独立确认；本轮文档不替代这些条件，也不授权下一轮运行或默认切换。
